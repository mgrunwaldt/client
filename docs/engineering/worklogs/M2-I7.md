# M2-I7 Player Client Worklog

## Issue Contract

Implement the player-client half of `mgrunwaldt/match_server#19`. The client
must rehydrate the exact backend-authoritative match projection after refresh
or reconnect, retain only verifiably safe local input, reconcile ambiguous
commands against `latest_operation`, and expose mobile-first recovery actions
without restarting or fabricating a match.

## Owned Paths

- `src/match/api-v1/**`: versioned snapshot/error/receipt contract and transport.
- `src/match/session-*.ts`: pure session recovery state, persisted pending
  command/draft boundary, and online/offline lifecycle.
- `src/app/(main)/Match/**`, `src/app/(main)/Pre-Match/**`, and
  `src/app/(game)/GameScene.tsx`: contract-driven recovery entry points only.
- `tests/**` and `e2e/**` that prove client hydration and recovery behavior.
- `docs/match-session-state-machine.md`: state-machine documentation.

The backend worktree, server behavior, simulation rules, Three.js stadium,
models, camera transform, and visual-asset pipeline are not owned by this
issue.

## Supported Authoritative States

`NOT_STARTED`, `IN_PROGRESS`, `WAITING_FOR_DECISION`,
`WAITING_FOR_RECOVERY`, `HALFTIME`, `FINISHED`, known playable scenes,
unavailable-Legend simulation, result playback reconstructed from a committed
decision receipt, and terminal administrative abandonment.

## Implementation Plan

1. Update the local Match API v1 runtime contract for required operation
   receipts and explicit server recovery metadata.
2. Add a bounded browser-session journal for a pending command and field draft.
   It stores no authoritative result and is valid only for the same match,
   revision, action, and command identity.
3. Make hydration authoritative: map every snapshot phase; restore local draft
   only after identity/revision validation; use a matching committed receipt to
   reconstruct result playback; otherwise expose only the exact retained retry.
4. Map backend recovery actions and browser transport failures to accessible
   recovery UI. Online listeners trigger one guarded hydrate and always clean up.
5. Add unit/contract tests and targeted Playwright coverage for refresh,
   offline/reconnect, retry/idempotency, stale/auth/terminal/error states.

## Test Plan

- Contract tests for receipts, `recovery_action`, and error maps.
- Reducer/store tests for phase hydration, draft validity, receipt reconciliation,
  exact retry, and listener cleanup.
- Browser tests at desktop and mobile viewports for named refresh phases and
  recoverable faults. Existing lifecycle/field behavior remains covered by
  affected regression suites.
- Pinned Node 22 `pnpm` format, lint, typecheck, unit, fixture, build, and
  focused Playwright checks.

## Browser Recovery Matrix

The Playwright projects run every row on desktop Chromium and mobile Chromium.
The matrix deliberately tests one network disruption at each control boundary
instead of multiplying every phase by every transport mode.

| Authoritative phase or fault                 | Browser evidence                                                                                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pre-match / pending start command            | `m2-i7-recovery.spec.ts` refreshes a real authoritative `NOT_STARTED` pre-match without issuing a start; `match-entry.spec.ts` covers retained start-command idempotency. |
| Timeline                                     | `m2-i7-recovery.spec.ts`: an offline GET never fabricates a timeline; reconnect hydrates once despite repeated `online` events.                                           |
| Aiming and contact draft                     | `m2-i7-recovery.spec.ts`: direct field refresh restores the exact retained contact grid selection only for the matching action/revision.                                  |
| Ambiguous kick submission / result receipt   | `m2-i7-recovery.spec.ts`: a timed-out single POST survives a real reload, reconciles a committed receipt, and restores that receipt after a second reload.                |
| Random event pending input                   | `m2-i7-recovery.spec.ts`: a real `/game/:id` hydration exposes authoritative random-scene choices on both viewports.                                                      |
| Dribble pending input                        | `m2-i7-recovery.spec.ts`: a real `/game/:id` hydration exposes authoritative dribble controls on both viewports.                                                          |
| Unsupported scene recovery                   | `m2-i7-recovery.spec.ts`: a timed-out recovery POST hydrates a durable `SKIPPED_NO_EFFECT` receipt, returns to Timeline, and never opens kick playback.                   |
| Halftime / unavailable simulation            | `match-lifecycle.spec.ts` and `m2-i7-recovery.spec.ts`: direct authoritative hydration and browser refresh render halftime and route the unavailable-Legend simulation.   |
| Full-time / abandonment boundary             | `match-lifecycle.spec.ts` and `m2-i7-recovery.spec.ts`: direct full-time snapshot and browser refresh route to the authoritative result, without a field state.           |
| 401, 403, 404, 409 stale, 429 throttled, 503 | `m2-i7-recovery.spec.ts`: each server `recovery_action` maps to a visible action; command-specific auth/stale flows are covered in the field recovery cases.              |
| Asset failure                                | `m2-i7-recovery.spec.ts`: a failed required ball model becomes field recovery UI rather than a blank WebGL surface.                                                       |

Network delay/timeout is applied at the ambiguous action and unsupported-scene
command boundaries. Browser offline/reconnect is applied to the already-loaded
Timeline route so the recovery UI itself remains available while the API fails.
