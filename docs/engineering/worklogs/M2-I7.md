# M2-I7 Player Client Worklog

## Issue Contract

Implement the player-client half of `mgrunwaldt/match_server#19`. The client
must rehydrate the exact backend-authoritative match projection after refresh
or reconnect, retain only verifiably safe local input, reconcile ambiguous
commands against `latest_operation`, and expose mobile-first recovery actions
without restarting or fabricating a match.

## Owned Paths

- `src/match/api-v1/**`: versioned snapshot/error/receipt contract and transport.
- `src/match/session-*.ts`: pure session recovery state, persisted pending
  command/draft boundary, and online/offline lifecycle.
- `src/app/(main)/Match/**`, `src/app/(main)/Pre-Match/**`, and
  `src/app/(game)/GameScene.tsx`: contract-driven recovery entry points only.
- `tests/**` and `e2e/**` that prove client hydration and recovery behavior.
- `docs/match-session-state-machine.md`: state-machine documentation.

The backend worktree, server behavior, simulation rules, Three.js stadium,
models, camera transform, and visual-asset pipeline are not owned by this
issue.

## Supported Authoritative States

`NOT_STARTED`, `IN_PROGRESS`, `WAITING_FOR_DECISION`,
`WAITING_FOR_RECOVERY`, `HALFTIME`, `FINISHED`, known playable scenes,
unavailable-Legend simulation, result playback reconstructed from a committed
decision receipt, and terminal administrative abandonment.

## Implementation Plan

1. Update the local Match API v1 runtime contract for required operation
   receipts and explicit server recovery metadata.
2. Add a bounded browser-session journal for a pending command and field draft.
   It stores no authoritative result and is valid only for the same match,
   revision, action, and command identity.
3. Make hydration authoritative: map every snapshot phase; restore local draft
   only after identity/revision validation; use a matching committed receipt to
   reconstruct result playback; otherwise expose only the exact retained retry.
4. Map backend recovery actions and browser transport failures to accessible
   recovery UI. Online listeners trigger one guarded hydrate and always clean up.
5. Add unit/contract tests and targeted Playwright coverage for refresh,
   offline/reconnect, retry/idempotency, stale/auth/terminal/error states.

## Blocking Review Remediation

The independent I7 review redirected the client work to five fail-closed
session invariants before the browser matrix can be accepted:

1. A valid committed action receipt restores normal result playback even when
   the local recovery journal has already been cleared.
2. Ambiguous dribble and random-event submissions expose only the exact
   retained command retry; a new payload can never reuse its idempotency key.
3. Start, resume, and action responses carry their originating command identity
   into the reducer so late responses after navigation, reset, or replacement
   cannot mutate the active session.
4. The legacy `/game` URL resolves safely instead of mounting an unhydrated
   field without a match identity.
5. Receipt playback is accepted only when its committed revision and submitted
   action/field identities agree with the authoritative match snapshot.

Owned remediation files are `src/match/session-machine.ts`,
`src/match/session-types.ts`, `src/match/session-store.ts`, the bounded async
call sites under `src/app/(main)/**` and `src/app/(game)/GameScene.tsx`, routing
in `src/app/app.tsx`/`src/routes.ts`, and their exact unit/E2E tests. The backend,
simulation, models, camera, and client-side persistence of result payloads remain
out of scope.

The remediation tests cover journal-less normal playback, inconsistent receipt
rejection, exact ambiguous random/dribble retry, late response suppression,
legacy `/game`, and real refresh during aiming, random-event, and dribble phases.

## Final Independent Review Remediation

A fresh independent review found four additional recovery-boundary defects. The
final implementation resolves each at the session contract rather than masking
it in an individual screen:

1. `ACTION_REQUESTED` accepts a recovery retry only when the retained command,
   payload, action, revision, and idempotency key are byte-for-byte equivalent
   to the command proven safe by hydration.
2. An immediate action response without its committed operation receipt fails
   closed in `recoverable_error`, retains the exact command, and never enters an
   empty result-playback phase. Normal and no-effect receipts are also checked
   against the exact submitted decision envelope.
3. `fetchBackendMatch(matchId)` rejects a valid-looking snapshot whose
   authoritative `match.id` differs from the route identity. Field interaction
   remains blocked while a new route identity hydrates.
4. Prematch and Result now use generation-aware in-flight locks. Repeated
   browser `online` events start one authoritative hydration, while later real
   reconnects remain possible after that request settles.

The same remediation also clears loading state on rejected field commands and
persists an acknowledged result receipt identity so a refresh cannot replay an
already-consumed result indefinitely.

## Route-Abandonment Remediation

The final directed pass fixed the remaining unmount races without weakening the
authoritative boundary:

1. Clearing a generic error can no longer unlock an ambiguous retained command.
   Only a hydrated `RETRY_SAME_REQUEST` diagnostic authorizes the exact retry.
2. Prematch, Timeline, and Field retain the exact in-flight command when their
   route is abandoned, clear screen-owned locks/loaders, and require an
   authoritative GET before another POST is possible.
3. Timeline treats both a transitional command and its immediate
   `HYDRATE_MATCH` recovery state as one stable reconciliation operation. Phase
   changes neither cancel the only useful GET nor issue duplicate GETs.
4. A committed action receipt discovered by that GET restores result playback
   and never reissues the action. A committed halftime transition restores the
   authoritative minute and timeline with one resume POST.
5. Blocking recovery UI takes precedence over staged result playback; automatic
   result continuation pauses until recovery has completed.
6. Mobile dribble movement uses explicit left/right screen-half taps instead
   of a swipe recognizer. The authoritative lane-switch cooldown still limits
   each tap to one adjacent lane, and the eight-second clock starts only after
   the field is render-ready.

## Final Client Findings Remediation

The final independent client review used the canonical M2 contract from
`mgrunwaldt/match_server@da5b16b:docs/product/M2_PRODUCT_SPEC.md`.
It found three remaining client boundaries:

1. A terminal `STOP` diagnostic on Result hid retry correctly but offered no
   mobile-safe exit. Result now always provides `Back to home`, while `STOP`
   continues to expose no retry or reauthentication substitution.
2. Cancelled hydration in Prematch, Timeline, and Result could leave the
   shared `loading` flag true. The session store now gives each hydration a
   monotonic ownership generation. Cleanup releases only its current
   generation; reducer, command, generic loading, and reset transitions
   invalidate older generations before they can clear a newer loader.
3. The mobile real-timer dribble test previously coupled its pre-deadline
   assertion to runner scheduling. It now records the browser's request time
   against the authoritative `runStartedAtMs`, proving the submission occurs
   between 7.9 and 10 seconds and exactly once even when CI pauses the runner.
   No production timing or eight-second timer behavior changed.

Focused browser evidence covers the Result `STOP` home exit on both viewport
classes and client-side route abandonment/re-entry for Prematch, Timeline, and
Result. The latter asserts that the abandoned request releases its own loader,
that re-entered surfaces report `data-session-loading=false`, and that Prematch
Play is enabled again.

## Isolated Linux Browser Remediation

The first eight-shard Linux run reduced the browser wall time from more than an
hour to roughly ten minutes and exposed two genuine mobile/browser boundaries
that grouped local runs had hidden:

1. The Drei `Html` aim target could be mounted in a portal one frame after the
   contact dialog closed. Focus restoration now retries on animation frames and
   consumes its restore request only after the connected aim target actually
   owns focus. The exact desktop/mobile browser case passes 2/2.
2. CDP mobile swipes did not provide a reliable production-equivalent event
   sequence. Product direction explicitly simplified the dribble control: the
   left and right halves of the field are now large tap targets that move one
   lane in that direction. Direct lane buttons and keyboard controls remain.
   The targets disable after submission, expose visible keyboard focus, respect
   the authoritative lane-switch cooldown, and ignore movement beyond the
   outer lanes without appending a trace point.

The screen-side tap E2E uses real desktop clicks and mobile taps, retains the
real eight-second animation-frame timer, verifies a single authoritative
submission, and keeps the existing player/HUD and result visual baselines.
It proves both directions with an exact `RIGHT -> CENTER -> RIGHT` trace plus
an outer-lane no-op. Focus restoration retries at a low fixed cadence for the
lifetime of the mounted target and clears its request only after the connected
Drei portal target owns focus; component cleanup cancels all pending work.
